# 当前 RTL 生效设计（2026-08-20）

## 1. 结论与范围

本文回答的是：**当前 Pure3 全栈链路及已生成的 Profile-5 BOOT.BIN 中，哪些手写 RTL 真正进入了有效硬件层级。**

当前板端 `INFO` 返回 `profile=0x00000005`，对应：

- Pure3（三颗等质量恒星，不含测试行星）；
- 高精度平滑力；
- 缓存加速度的 Leapfrog 积分器；
- 单 fitness lane；
- 32 个个体、每个个体 8 个 32 位基因；
- 100 MHz PL 时钟；
- PS7 + AXI DMA + AXI-Lite + Pure3 PL 的完整链路。

当前真正实现上述 Profile-5 PL 功能的手写 RTL 共 **7 个文件**：

| 序号 | 生效文件 | 当前职责 |
|---:|---|---|
| 1 | `rtl/top/ga3b_v1_min_accel_top.v` | 全栈 PL 顶层；连接 AXI DMA 流接口、AXI-Lite 寄存器、状态与中断 |
| 2 | `rtl/pure3_core/ga3b_pure3_rf_accel_top.v` | 任务包解包、参数校验、启动 GA、结果包打包 |
| 3 | `rtl/pure3_core/ga3b_pure3_rf_ga_core.v` | 32 个体 GA、双 population BRAM、均匀初始化、选择/交叉/变异/精英保留 |
| 4 | `rtl/ga_core/ga3b_rng_xorshift32.v` | GA 随机数发生器 |
| 5 | `rtl/pure3_core/ga3b_pure3_hifi_fitness_lane.v` | Profile-5 三体积分、碰撞/逃逸判定、生存 fitness 累计 |
| 6 | `rtl/pure3_core/ga3b_pure3_hifi_force_pair.v` | 共享两体作用力流水数据通路，计算 `GM * delta / r^3` |
| 7 | `rtl/pure3_core/ga3b_pure3_inv_r3_lut.v` | `1/r^3` 归一化查表及插值端点 ROM |

## 2. 当前有效 RTL 层级

```text
ga3b_system_wrapper                         Vivado BD 自动生成顶层
└─ ga3b_system_ga3b_accel_0_0              BD module-reference 包装器（自动生成）
   └─ ga3b_v1_min_accel_top                rtl/top
      └─ ga3b_pure3_rf_accel_top           rtl/pure3_core
         └─ ga3b_pure3_rf_ga_core          rtl/pure3_core
            ├─ ga3b_pure3_rf_pop_ram × 2   与 GA core 位于同一 .v 文件
            ├─ ga3b_rng_xorshift32         rtl/ga_core
            └─ g_hifi_lane                 HIFI_ENABLE=1，当前被展开
               └─ ga3b_pure3_hifi_fitness_lane
                  └─ ga3b_pure3_hifi_force_pair
                     └─ ga3b_pure3_inv_r3_lut
```

BD 内还包含 Xilinx 自动生成/厂商 IP：PS7、AXI DMA、AXI interconnect、reset、interrupt concat 等。它们是完整系统的一部分，但不是仓库中的手写 RTL。

## 3. 为什么确定当前是 Profile 5

### 3.1 源码默认值不等于当前部署值

`ga3b_v1_min_accel_top.v` 的源码默认参数是：

```verilog
HIFI_ENABLE     = 1
INTEGRATOR_MODE = 0
```

默认值本身对应 Profile 4（高精度平滑力 + 辛 Euler）。但是当前 BD 生成包装器中实际覆写为：

```verilog
.HIFI_ENABLE(1),
.INTEGRATOR_MODE(1)
```

因此当前综合、布局布线、bitstream 和 SD 卡 BOOT.BIN 使用的是 **Profile 5：缓存加速度 Leapfrog**，而不是源码默认的 Profile 4。

该覆写由以下脚本完成：

- `vivado/scripts/configure_v1_hifi_variant.tcl`
- `scripts/run/set_v1_hifi_generated_variant.ps1`，参数 `-Mode 1`

当前本地生成包装器证据：

```text
vivado/runs/v1_min_bd/ga3b_v1_min_bd.gen/sources_1/bd/ga3b_system/ip/
ga3b_system_ga3b_accel_0_0/synth/ga3b_system_ga3b_accel_0_0.v
```

### 3.2 Profile 寄存器编码

`ga3b_v1_min_accel_top.v` 中的硬件编码为：

| Profile | `HIFI_ENABLE` | `INTEGRATOR_MODE` | 含义 |
|---:|---:|---:|---|
| 3 | 0 | 任意 | 旧 Pure3 RF fitness lane |
| 4 | 1 | 0 | 高精度平滑力 + 辛 Euler |
| 5 | 1 | 1 | 高精度平滑力 + 缓存加速度 Leapfrog |

板端冷启动后的 `INFO profile=0x00000005` 与生成包装器完全一致。

## 4. 各生效文件的实际功能

### 4.1 `ga3b_v1_min_accel_top.v`

- 作为 BD 中 `ga3b_accel_0` 的 module reference；
- 接收 AXI DMA 的 `S_AXIS` 任务流，输出 `M_AXIS` 结果流；
- 提供 AXI-Lite 控制/状态寄存器；
- 提供任务完成中断；
- 公开版本、Profile 和原始状态；
- 实例化 `ga3b_pure3_rf_accel_top`。

主要寄存器：

| 偏移 | 寄存器 | 作用 |
|---:|---|---|
| `0x00` | CTRL | enable、IRQ enable、clear done、soft reset |
| `0x04` | STATUS | 当前加速器状态 |
| `0x08` | VERSION | 当前为 `0x00010000` |
| `0x0C` | PROFILE | 当前应读到 `5` |
| `0x10` | RAW | 原始诊断状态 |

### 4.2 `ga3b_pure3_rf_accel_top.v`

- 校验任务魔数 `0x47413342`（`GA3B`）；
- 解包 `max_gen`、`steps`、Q16 变异率/交叉率、两个 seed；
- 解包 8 个基因的上下界和变异尺度；
- 检查 `GENE_COUNT=8`、`POP_SIZE=32`；
- 启动 GA core；
- 将最佳 fitness、生存步数、最佳索引和 8 个基因打包为结果；
- 结果魔数为 `0x52534C54`（`RSLT`）。

### 4.3 `ga3b_pure3_rf_ga_core.v`

- `POP_SIZE=32`，`GENE_COUNT=8`，当前一条 fitness lane；
- 两个 population bank 由文件内的 `ga3b_pure3_rf_pop_ram` 实现，并按双口 BRAM 推断；
- 使用整个 `[gene_min, gene_max]` 区间做均匀初始化，而非集中在端点；
- 个体 0 初始化为区间中点；
- tournament-3 选择；
- 每基因交叉和变异，结果钳位到边界；
- 精英保留：下一代个体 0 复制全局最佳染色体；
- 记录全局最佳 fitness、存活步数和染色体；
- `HIFI_ENABLE=1` 时展开高精度 lane；当前就是这条 generate 分支。

### 4.4 `ga3b_rng_xorshift32.v`

- 使用 xorshift32：左移 13、右移 17、左移 5；
- 实际种子为 `seed0 ^ {seed1[15:0], seed1[31:16]}`；
- 避免全零锁死状态，零值替换为 `0x1BADF00D`。

### 4.5 `ga3b_pure3_hifi_fitness_lane.v`

- 三颗等质量恒星，第三颗的位置/速度由前两颗推导，使质心和总动量为零；
- 使用 48 位有符号状态和 32 位小数精度；
- 当前 `INTEGRATOR_MODE=1`：
  1. 先计算并缓存初始加速度；
  2. 漂移位置；
  3. 重新计算加速度；
  4. 用旧、新加速度平均值更新速度；
  5. 缓存新加速度供下一步使用；
- 三对天体依次复用一个 force-pair 数据通路；
- 碰撞使用 L1 距离阈值 `0.125`；
- 任一位置分量绝对值超过 `8.0` 判为逃逸；
- 完整存活时 fitness 为 `0x0000000100000000 + survived_steps`，否则主要由存活步数决定。

注意：文件头旧注释曾写作“Q16.32”；以代码位宽和移位行为看，更准确的说法是 **48 位有符号容器、32 位小数**。

### 4.6 `ga3b_pure3_hifi_force_pair.v`

- 计算两体相对位移和 `r²`；
- 对极小 `r²` 做 soft clamp；
- 归一化 `r²`，获得 LUT 地址、插值系数和指数缩放；
- 复用注册乘法器依次计算 X/Y 方向力；
- 输出 `GM * delta / |delta|³`；
- 当前一个 lane 内仅共享一套该单元，以节省 Zynq-7020 资源。

### 4.7 `ga3b_pure3_inv_r3_lut.v`

- 保存 `1/r³` 近似所需的 256 段端点；
- 作为 block ROM 推断；
- 配合 force-pair 完成线性插值；
- 由 `scripts/gen/gen_pure3_inv_r3_lut.py` 生成，**不应手工修改表项**。

## 5. PS、DMA 与 PL 的当前连接

`vivado/scripts/create_v1_min_bd.tcl` 建立的完整链路为：

```text
PS DDR
  ↕ HP0
AXI DMA MM2S ──AXI4-Stream──> ga3b_v1_min_accel_top
AXI DMA S2MM <─AXI4-Stream─── ga3b_v1_min_accel_top

PS GP0 ──AXI-Lite──> AXI DMA 控制寄存器（0x40400000）
PS GP0 ──AXI-Lite──> GA3B 控制寄存器（0x43C00000）

DMA MM2S IRQ ┐
DMA S2MM IRQ ├─> xlconcat -> PS IRQ_F2P
GA3B done IRQ┘
```

- 器件：`xc7z020clg400-2`；
- FCLK0：100 MHz；
- AXI DMA：simple mode，32 位 stream；
- Pure3 RTL 不直接访问 DDR，任务和结果均由 PS 经 DMA 搬运。

## 6. 被读取但在当前 Profile-5 中不形成有效逻辑的文件

### 6.1 编译时备用分支

`rtl/pure3_core/ga3b_pure3_rf_fitness_lane.v` 会被 filelist/综合工程读入，用于 `HIFI_ENABLE=0` 的 Profile-3 分支。当前 `HIFI_ENABLE=1`，所以该模块**不会进入当前有效网表**。

### 6.2 旧版或其他模型 RTL

以下文件不属于当前 Profile-5 的综合层级：

- `rtl/ga_core/ga3b_ga_core.v`
- `rtl/ga_core/ga3b_fitness_lane.v`
- `rtl/ga_core/ga3b_heng_era_fitness_lane*.v`
- `rtl/ga_core/ga3b_heng_era_metric_accumulator.v`
- `rtl/ga_core/ga3b_sun3_integrator.v`
- `rtl/ga_core/ga3b_test_planet_integrator.v`
- `rtl/ga_core/ga3b_pure3_fallback_fitness_lane.v`
- `rtl/top/ga3b_heng_era_accel_top.v`

它们分别服务于旧 v0.3、受限四体/测试行星、旧 Pure3 fallback 或独立验证流程。保留它们不会影响当前 Profile-5 bitstream，但不能将“仓库里存在”误认为“当前板上生效”。

## 8. 重要维护注意事项

1. **不要只看 RTL 顶层默认参数。** 当前 Profile 5 依赖生成包装器中的 `INTEGRATOR_MODE(1)` 覆写。
2. 清理/重建 Vivado generated output 后，必须重新执行 Profile-5 参数化脚本，否则可能退回 Profile 4。
3. 推荐的构建顺序是：创建/打开 BD → 配置 HiFi 文件 → 生成 target → `set_v1_hifi_generated_variant.ps1 -Mode 1` → OOC 综合 → 顶层综合/布局布线 → bitstream/XSA。
4. 生成的 BD 包装器通常不进入 Git；因此新环境必须依赖脚本复现，不能依赖旧 generated 文件恰好存在。
5. 当前 PL 硬件 fitness 本质仍以“生存步数/是否完整存活”为核心。Web 前端展示的长时生存、安全擦掠、三星纠缠、近周期回归等分类，还包含 PC 端轨迹重放和指标判定，不等价于四套独立硬件 fitness。
6. `ps_app/common/ga3b_protocol.h` 属于 PS/软件协议，不是 RTL；本文没有修改该文件。
