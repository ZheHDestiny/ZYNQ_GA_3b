# ZYNQ_GA_3b 目前情况与交接说明

更新时间：2026-08-15  
目标板：正点原子领航者 V2，Zynq-7020（`xc7z020clg400-2`）  
当前硬件 profile：`5 / pure3_hifi_leapfrog_cached`

## 1. 项目目标与当前取舍

项目目标是用 PS+PL 遗传算法搜索三体/受限四体系统中具有长生存、
安全近掠、三星纠缠或近周期回归特征的初始条件，并由 PC Web 页面展示轨迹、
遥测和端到端性能。

受限四体版本仍保留在工程中，但 Zynq-7020 的当前可部署主线是 Pure3：三颗
等质量太阳、质心和总动量约束、8 个 Q16.16 输入基因。选择 Pure3 是资源适配
退化方案，不代表最初受限四体科学目标被删除。

## 2. 当前可工作的端到端链路

```text
Web browser
  -> Flask HTTP backend
  -> COM13 / 115200 UART
  -> standalone board_agent
  -> AXI DMA MM2S/S2MM
  -> Profile-5 Pure3 GA accelerator
  -> UART result
  -> PC Profile-5 trajectory replay/classification
  -> Web animation and telemetry
```

SD 冷启动的 `BOOT.BIN` 包含 FSBL、Profile-5 bitstream 和 standalone
board-agent ELF。JTAG 只用于开发/恢复，不是正常演示的必需连接。

## 3. Profile-5 数值与 GA 契约

### 积分器

- 输入染色体：8×32-bit Q16.16；
- lane 内部状态：Q32.32；
- 力模型：规格化平滑 `GM/r^3` LUT，1025 个插值端点；
- 积分：缓存加速度 Leapfrog；
- `dt = 1/256`，`GM = 1/256`；
- 碰撞条件：两体 L1 距离 `< 0.125`；
- 逃逸条件：任一位置分量绝对值 `> 8.0`。

### GA

- 种群：32；
- 初代个体 0 为区间中点；
- 其余个体用全 32 位 PRNG 在每个基因完整 `[min,max)` 中均匀初始化；
- candidate 评估数为 `32 * (max_gen + 1)`；
- RNG 初态为 `seed0 XOR swap16(seed1)`；
- 多起点搜索的第 0 个候选严格使用用户 seed，后续候选才派生 seed。

### 概率输入

浏览器现在使用 `0.00%..100.00%`，保留两位小数。后端负责译码：

```text
q16 = round(percent * 65536 / 100)
100% -> 65535（饱和）
```

直接 API/预设仍兼容 `mutation_q16` 和 `crossover_q16`。当前推荐值：

```text
mutation = 31.25% -> 20480
crossover = 87.50% -> 57344
```

## 7. 长窗口科学结果

第一次 `max_gen=1, steps=100000` 只评估 64 个候选，最优解在 3667 步逃逸；
FPGA 与 PC 重放一致，因此不是积分器或前端错误。

推荐 seed：

```text
seed0 = 2995967490
seed1 = 1001641397
```

消融结果：

| max_gen | mutation | crossover | 100000 步请求的存活数 |
|---:|---:|---:|---:|
| 8 | 6.25% | 75.00% | 11356 |
| 16 | 18.75% | 81.25% | 50811 |
| 32 | 31.25% | 87.50% | 100000 |
| 64 | 31.25% | 87.50% | 100000 |

最佳染色体：

```text
Q16 integer: [-244, 40654, 3309, -5090, 20358, 65850, -397, 4024]
decimal: [-0.0037231445, 0.6203308105, 0.0504913330, -0.0776672363,
          0.3106384277, 1.0047912598, -0.0060577393, 0.0614013672]
```

该染色体已在 FPGA 和 PC 完整通过 100000、131072、262144、524288、
1048576 步。百万步 PC 指标：

```text
relative energy drift = 1.27e-7
minimum pair distance = 0.314
compact fraction = 100%
close passes = 68
winding = 411.6 rad
angular-order exchanges = 215
```

2097152 步请求触发 board-agent `code=-12`，原因是
`GA3B_DMA_TIMEOUT=200000000` 耗尽，不是物理碰撞/逃逸。超时后 DMA channel
会保持 Busy，软件 `RESET` 不能恢复，必须物理断电冷启动。当前开发板在最后
一次测试后正处于这种状态；下一位接手者应先冷启动，再执行 PING/INFO/SELFTEST。

## 8. HTTP/Web 当前状态

启动前关闭所有占用 COM13 的串口终端：

```powershell

.\scripts\run\run_v1_web_demo.ps1 -Port COM13
```

浏览器打开 `http://127.0.0.1:8000/`。主要 API：

```text

POST /api/custom-replay
POST /api/performance/probe
GET  /api/presets

GET  /api/results
```

页面目前支持：四类目标、模范解实板复现、事件高亮/完整轨迹切换、播放速度、
十进制初态、轨迹指标、系统信息、网页版 README、性能探针和 SQLite 结果保存。

本轮前端更新：

- 变异率/交叉率改为带 `%` 的 0.00–100.00 输入；
- seed 改名为“复现实验种子主字/混合字”，统一显示无符号十进制；
- 后端兼容百分比译码和旧 Q16 API；
- 100000 步、64 代、8 个多起点的估算由错误的 124.7 s 校准为保守 470.0 s；
- 校准实测端到端为 457.332 s；估算文本明确标记“保守预计”。
- 修复轨迹暂停后恢复时按暂停期间墙钟时间追帧而导致的瞬移；暂停期间现在持续
  重置动画时钟，恢复播放从当前帧连续前进，拖动时间轴也会进入真正的暂停状态。

当前 HTTP 搜索上限仍为 131072 步。百万步只通过直接 UART 扫描验证，尚未开放
给同步 Web 请求。若要开放，应先解决 board-agent 超时、DMA 超时恢复和异步任务。

## 9. 性能探针结果与边界

标准 288 candidates / 8192-step cap：

| 路径 | 耗时 | 吞吐 |
|---|---:|---:|
| Zynq-7020，完整 GA+DMA+UART | 1090.30 ms | 264.15 eval/s |
| Python Profile-5 标量参考 | 69959.41 ms | 4.12 eval/s |
| NumPy float64 批处理代理 | 1807.17 ms | 159.37 eval/s |

该工作负载下 FPGA 约为标量参考 64.2 倍、NumPy 代理 1.66 倍。NumPy 不是 LUT
位精确模型，软件路径也不含 GA 选择/繁殖和 UART/DMA，因此不得把该数字宣传为
算法完全等价或通用算力加速比。

## 11. 已知缺口与建议优先级

1. 修改 board-agent：使用定时器/中断或可配置超时，超时时同时复位 AXI DMA；
2. 将长窗口搜索改成异步作业，避免 600 s 内同步 HTTP 请求；
3. 实现分层 fitness：短窗口淘汰、长窗口晋级、高精度复核；
4. 将安全擦掠、纠缠、回归判据逐步下沉为真正硬件 fitness，而非只做 PC 重排；
5. 增加任意染色体直接注入 PL lane 的协议；当前自定义初态只做 PC Profile-5 重放；
6. 在资源允许时重新评估受限四体版本；资源不足则继续以 Pure3 为交付主线；
7. 对百万步候选做独立高精度浮点/多精度复核，区分有限精度周期锁定与真实轨道。
